# 系统报告整合规范（P2-15 / KA-80）

> **所属**：智能评分系统（评分方案 C）
> **需求来源**：《开发需求清单 v1.0》P2-15（KA-80）
> **文档版本**：v1.0
> **维护**：技术文档撰写者（随系统变更同步更新）
> **验收**：项目负责人
> **配套**：`docs/report-templates/`（周报/月报/季度报告三份统一模板）

---

## 一、目的与范围

评分系统运行至今，报告散落在多个目录与口径下（监控周报在 `monitor/`，月度/季度评分报告在
`reviews/scoring/`，自我审查在 `agents/reviews/`），各报告结构不一、归档位置不统一，检索与
跨期对比成本高。本规范将三类**系统运行报告**——周报 / 月报 / 季度报告——统一为同一套输出骨架、
同一套命名规范与同一套归档口径，作为运行态报告的单一事实来源。

**适用对象**：

| 报告类型 | 周期 | 是否为本规范范围 | 说明 |
|----------|------|:---:|------|
| 系统监控周报（P2-13） | 每周 | ✅ | 由 SRE稳定性工程师 + 数据可视化工程师产出 |
| 月度百分制报告（R-41） | 每月末 | ✅ | 由聚合器 `rating-aggregator.py` 自动产出 |
| 季度综合评分报告（R-51 + 人评） | 每季末 | ✅ | 由聚合器 + 季度人评判定器 `quarterly-review-judge.py` 产出 |
| 智能体月度自我审查 | 每月末 | ⚠️ 关联 | 走 `agents/reviews/monthly/`，不归本规范统一，但归档索引纳入 README |
| 季度复盘报告（P3-16~18） | 每季末 | ⚠️ 关联 | 走 P3 立项，格式沿用季度报告骨架 |

**读者**：项目负责人（验收）、资深战略领导者（最高决策者 / 运行态负责人）、SRE稳定性工程师、
数据可视化工程师、数据工程师（P2-13 周报执行人），以及所有需要查证系统运行态的人员。

## 二、报告分类与口径总表

| # | 报告类型 | 周期 | 执行人(R) | 数据来源 | 产出物（命名规范） | 归档 |
|---|----------|------|-----------|----------|--------------------|------|
| 1 | 系统监控周报 | 每周五 | SRE稳定性工程师 + 数据可视化工程师 | 三任务日志 / autopilot runs / `audit-events.py` / 流水完整性对账 | `monitor-report-{YYYY-Wxx}.md` | 产物入 GitHub Release |
| 2 | 月度百分制报告 | 每月最后一天 | 自动化（`rating-aggregator.py` R-41） | 事件流水 `reviews/scoring/events/` | `reviews/scoring/monthly/{智能体}/{YYYY-MM}.md` | 产物入 GitHub Release |
| 3 | 季度综合评分报告 | 季末最后 3 天窗口 | 自动化（R-51）+ 季度人评（P1-9 judge） | 月度报告 + 季度人评表单 | `reviews/scoring/quarterly/{智能体}/{YYYY-Qn}.md` | 产物入 GitHub Release |
| 4 | 月度自我审查 | 每月最后一天 | 各智能体本人 | 【自评】+ 协作反馈 | `agents/reviews/monthly/{智能体}-{YYYY-MM}.md` | 入库（README 索引） |
| 5 | 季度复盘报告 | 每季末 | 数据工程师 + 事故响应指挥官（P3） | 全季度运行数据 | `docs/reviews/{YYYY-Qn}/复盘.md` | 入库（README 索引） |

> **口径说明**
> - 报告 1 的指标口径（on-time 执行率、结算失败数、escalated 数、pending 滞留、流水完整性）沿用
>   `docs/runbook.md` §6「监控与周报」，不另立口径。
> - 报告 2/3 的评分口径（R-41 / R-51 / 综合分 / 等级 / 防失真）沿用聚合器与判定器代码实现，
>   以 `docs/dashboard-data-interface.md` §3「数据来源」为准。
> - 报告 4 为能力档案体系的一部分，格式由 `agents/capability-system/template.md` 与自优化协议定义。

## 三、统一输出骨架（三类报告共用）

所有报告遵循同一条六段骨架，`#1/#2/#5/#6` 四段三类完全一致，`#3 明细` 与 `#4 风险与异常`
按报告类型填各自内容：

```text
1. 报告头（front-matter 元信息）
2. 关键指标摘要（KPI 表）
3. 明细分节（按类型：任务执行明细 / 智能体分数表 / 等级分布表）
4. 风险与异常（escalated / pending 滞留 / E-01~E-07 / R-71/R-72 / 失火）
5. 结论与行动项
6. 归档信息（生成方 / 归档位置 / Release 链接）
```

### 3.1 报告头（front-matter）

每份报告正文首部必须包含以下元信息块（建议以引用块呈现），保证跨期/跨类型机器可读与人工可检索：

| 字段 | 取值示例 | 必填 |
|------|----------|:---:|
| 报告类型 | 周报 / 月报 / 季度报告 | ✅ |
| 周期编号 | `2026-W34` / `2026-08` / `2026-Q3` | ✅ |
| 生成时间 | `2026-08-17T04:00:00Z`（UTC ISO8601） | ✅ |
| 生成方 | 自动化（`rating-aggregator.py`）/ 执行人 | ✅ |
| 数据来源 | 事件流水 / 三任务日志 / audit-events | ✅ |
| 归档位置 | GitHub Release tag / 仓库路径 | ✅ |

### 3.2 关键指标摘要（KPI 表）

三类报告的 KPI 见各模板；统一要求：**只放可在报告正文复现的指标**，数值与明细分节一致
（口径同源，禁止摘要与明细冲突）。

### 3.3 风险与异常（统一事件分类）

- **升级事件**：`escalated` 状态事件（含 pending > 48h）→ 周报必须列出，升级路径见 `docs/runbook.md` §3（P2-14 交付后并入 SLA 制度）。
- **异常标记**：E-01~E-07（聚合器/判定器产出）→ 月报、季度报告必须列出并分类计数。
- **防失真标记**：R-71 红线上限 C / R-72 缺自评降档 → 季度报告必须列出。
- **静默失火（L3）**：当日应有 run 但无日志/无 run → 周报必须显式核验（静默 = 故障）。

### 3.4 结论与行动项

每条行动项带负责人与截止时间；下期报告对上一期行动项做回执（done / 未完成原因）。

## 四、归档口径与 README 索引

### 4.1 归档总原则

| 内容 | 归档位置 | 入库? | 执行 |
|------|----------|:---:|------|
| 本规范 + 三份模板 | `docs/system-report-spec.md` + `docs/report-templates/` | ✅ 入库 | 技术文档撰写者 → GitHub 仓库管理员 |
| 系统监控周报（产物） | GitHub Release（tag `reports-{YYYY}-Q{n}`） | ❌ 不入库（`reports/` 已 gitignore） | SRE/数据可视化 → 仓库管理员 |
| 月度/季度评分报告（产物） | GitHub Release（tag `reports-{YYYY}-Q{n}`） | ❌ 不入库 | 自动化产出 → 仓库管理员 |
| 月度自我审查 | `agents/reviews/monthly/` | ✅ 入库 | 各智能体 → 仓库管理员 |
| 季度复盘报告 | `docs/reviews/` | ✅ 入库 | P3 执行人 → 仓库管理员 |
| README 索引 | 根 `README.md`「系统报告」节 | ✅ 入库 | 技术文档撰写者维护 |

### 4.2 归档流程（产物 → Release）

1. 生成：周报由 SRE/数据可视化按模板产出；月报/季度报告由 cron 聚合产出。
2. 校验：周报核对 runbook §6 指标口径；评分报告核对 `audit-events.py` 流水完整性（重复 = 0）。
3. 打包：按季度打包，命名 `reports-{YYYY}-Q{n}.tar.gz`。
4. 归档：GitHub 仓库管理员发布 GitHub Release（tag `reports-{YYYY}-Q{n}`），并在根 README
   「系统报告」节追加一条归档链接。

### 4.3 README 索引（根 README「系统报告」节）

根 README「系统报告」节是三类报告的唯一检索入口，包含：

- 三类报告 × 周期 × 执行人的一览表（同 §二）；
- 指向本规范与三份模板的链接；
- 最新 Release 归档链接（由 4.2 流程维护）。

## 六、模板使用方式

- 周报执行人（SRE + 数据可视化）：复制 `weekly-report-template.md`，按周填数。
- 月报/季度报告：聚合器/判定器自动生成；模板作为人工抽查与格式对齐的参照（自动报告结构若与模板
  骨架有差异，以本规范「统一输出骨架」为准）。
- 模板变更：由技术文档撰写者统一维护，变更前先与执行人（P2-13）与验收人（项目负责人）对齐。
