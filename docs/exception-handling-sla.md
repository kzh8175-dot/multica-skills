# 评分系统异常处理 SLA

> **所属**：智能评分系统（评分方案 C）
> **需求来源**：《开发需求清单 v1.0》P2-14（KA-79，KA-8 清单项）
> **前置**：P0 + P1 全部完成 ✅
> **执行人（R）**：技术文档撰写者（文档）+ 事故响应指挥官（响应侧设计）
> **负责人（A）/ 验收人**：资深战略领导者
> **文档版本**：v1.0（合并定稿）
> **维护**：技术文档撰写者（随运行态 / 规则变更同步更新）

## 一、文档目的与读者

本 SLA 定义评分系统**异常从发现到闭环**的处置规范：异常分级（S1~S4）、响应/处置/恢复时限、升级路径（L0~L4）、评分数据异常（E-01~E-07）的裁定口径、结算器错误码处置，以及事后复盘（blameless）要求。

**读者**：值班处置方（运行 agent / DevOps自动化工程师 / SRE稳定性工程师 / 最小变更工程师）、事故响应指挥官、项目负责人、资深战略领导者（最高决策者 / 终裁）。

**配套文档**：
- 定时任务 Runbook：`docs/runbook.md`（三任务 cron、手动触发、幂等判定、监控周报）
- 负责人评审指引：`agents/capability-system/reviewer-guide.md`（行为事件写入、权限红线、E 系列升级口径）
- 结算器：`src/rating-settler.py`（`pending → credited/escalated` 状态机）
- 防失真模块：`src/anti-distortion-rules.py`（E-02/E-05/E-06 自动化修正，唯一权威）

## 二、异常分类

异常分两大类，处置口径不同：

| 类别 | 范围 | 发现途径 | 处置主线 |
|------|------|----------|----------|
| **A · 运行态异常** | 三定时任务失败/静默失火、结算器错误码、API/写入失败、数据流水异常 | cron 包装脚本退出码、日志缺失、autopilot runs、日检/周检 | 分级 S1~S4 → L0~L4 升级路径（第 4~6 节） |
| **B · 评分数据异常** | E-01~E-07（流水缺失、评分人不足、档案缺失、等级 D、防失真触发、背离） | 月/季聚合报告、季度人评表单、`audit-events.py` | E 系列逐条裁定（第 7 节） |

## 三、角色与责任（RACI）

| 角色 | 处置职责 | 升级权限 |
|------|----------|----------|
| **运行 agent / 值班方** | 一线发现与初步处置（诊断、补跑、创建告警 issue） | 24h 未处置 → 升级 |
| **DevOps自动化工程师 / 最小变更工程师** | 部署维护三任务、包装脚本、cron/autopilot 配置修复、幂等补跑 | 24h 未处置 → 升级 |
| **SRE稳定性工程师** | SLO/错误预算、可观测性、日检/周检、静默失火补触发 | 24h 未处置 → 升级 |
| **事故响应指挥官** | **分诊定级、跨职能协调、全程通报**；`escalated` 积分争议处置；blameless 复盘主持；SLA 达成核对 | 按 S 级升级 |
| **数据工程师** | 事件流水归属/完整性修复（`audit-events.py --reconcile`）、E-01/E-03 数据协助 | 无法裁定 → 升级 |
| **项目负责人** | E-01/E-03/E-07 等数据异常裁定、补记/排除决策 | 无法裁定 → 升级最高决策者 |
| **资深战略领导者** | **最高决策者 / 终裁**：E-01~E-07 异常终裁、`escalated` 事件处置、等级 S/D 复核、重大升级裁决、复盘结论批准 | — |

## 四、异常分级（Severity · S1~S4）

| 级别 | 名称 | 判定标准（示例） | 影响 |
|:---:|------|------------------|------|
| **S1** | 严重 / 阻断 | 数据被破坏或评分结果错误：结算金额错误入账、流水跨文件重复或丢失、聚合结果错误覆盖月度/季度分、权限类异常 | 评分结果直接失真，须紧急止损 |
| **S2** | 高 | 核心功能异常但可降级：单次定时任务失败、`escalated` 事件堆积、pending 滞留 >48h、E_API/E_WRITE 指数退避后仍持续失败 | 结算/评分延迟，局部事件受影响 |
| **S3** | 中 | 局部异常：单智能体事件归属异常、未知智能体待归属清单、非关键路径告警噪声 | 不影响整体评分，需人工核验 |
| **S4** | 低 | 咨询/优化建议/非阻塞提示：规则校准建议、报告格式问题 | 无功能影响 |

> 评分数据异常（B 类）定级规则：触发 E-04（等级 D）或疑似数据错乱 → **S1/S2**；E-01/E-03/E-07 待裁定 → **S3**；仅自动化修正（E-02/E-05/E-06）→ **S4**（无需升级）。

## 五、响应矩阵

| 级别 | 响应（ack） | 处置（resolve） | 恢复（recover） | 一线责任人 | 指挥 / 二线 | 升级条件 |
|:---:|:---:|:---:|:---:|-----------|-----------|---------|
| **S1** | ≤4h | ≤24h | ≤48h（含数据复核） | SRE稳定性工程师 / DevOps自动化工程师 | 事故响应指挥官 | **12h 未定位根因 → 升级资深战略领导者** |
| **S2** | ≤24h | ≤48h | ≤72h | DevOps自动化工程师 / 最小变更工程师 / 数据工程师 | 事故响应指挥官（跟踪） | **48h 未处置 → 升级资深战略领导者** |
| **S3** | ≤48h | ≤72h | ≤5 个工作日 | 指定责任人（数据工程师等） | — | **72h 未处置 → 升级** |
| **S4** | ≤72h | 下个迭代 | 下个迭代 | 指定负责人 | — | 无 |

> **时限口径**：响应（ack）= 有人员接手并确认问题的时限；处置（resolve）= 完成修复/裁定并闭环的时限；恢复（recover）= 数据复核与验证完成、结果可信的时限。时限自告警/发现时刻起算；非工作时间顺延按第 12 节待校准项 2 执行。

## 六、升级路径（L0~L4）

```
L0 自动恢复  指数退避重试（30/60/120s，≤3 次）；E_DUP 幂等跳过 → 成功即闭环，无需告警
   │
L1 一线响应  监控/autopilot 告警 → SRE/DevOps 快速恢复（补跑、重试、幂等处置）
   │          24h 内闭环；失败创建「评分定时任务失败」issue（P1，assignee=SRE）
   │
L2 二线指挥  事故响应指挥官介入：分诊定级、跨职能协调、全程通报
   │          · S1 立即介入指挥；escalated 事件 48h 内完成响应
   │          · 未闭环前持续跟踪
   │
L3 三线终裁  资深战略领导者：终裁争议、重大升级裁决、资源协调
   │          · 触发：S1 12h 未定位根因 / S2 48h 未处置 / escalated 48h 未裁定 / 重大争议需终裁
   │
L4 复盘闭环  事故响应指挥官主持 blameless postmortem
               · 触发：所有 S1、当月 ≥1 次失火、escalated 事件结案
               · 输出：根因 + 行动项 + 责任人 + 截止时间，跟进到闭环
```

## 七、评分数据异常 · E 系列处置（E-01~E-07）

| 异常 | 名称 | 触发条件 | 处置动作 | 时限 | 裁定人 |
|:---:|------|----------|----------|:---:|--------|
| E-01 | 流水缺失 | 月/季流水缺失、缺失月份 | 补记缺失流水，或裁定排除该月（不计入 R-51 分母） | 48h（季评窗口内） | 项目负责人（数据工程师协助） |
| E-02 | 评分人不足 | 季度表单单评分人 | **自动化**：等级上限 A（E-02 → R-72 → R-71 顺序修正），无需人工 | 自动 | — |
| E-03 | 档案缺失 | 智能体能力档案缺失 | 先创建档案再评分；关键词推断兜底并标记 | 48h | 智能体本人 + 项目负责人 |
| E-04 | 等级 D | 季度等级 = D | **S1/S2**：升级资深战略领导者专项复盘（含 R-72 撞 D 地板场景） | 48h | 资深战略领导者 |
| E-05 | 违规 ≥2 次 | R-31 季度计数 ≥2 | **自动化**：R-71 等级上限 C | 自动 | — |
| E-06 | 缺自评 ≥2 次 | R-32 季度计数 ≥2 | **自动化**：R-72 降一档（D 为地板） | 自动 | — |
| E-07 | 背离 ≥40 分 | 人评与客观分背离 ≥40 分 | 复核评分来源与流水，必要时升级最高决策者 | 48h | 项目负责人 / 资深战略领导者 |

> **自动化项（E-02/E-05/E-06）** 由 `src/anti-distortion-rules.py` 在季度人评时自动施加，人工仅核验修正留痕（`corrections` 决策日志），无需走升级。

## 八、结算器错误码处置

| 错误码 | 含义 | 可重试 | 处置 |
|:---:|------|:---:|------|
| `E_PARSE` | 值格式错误（非整数 points、trigger 非法等） | 否 | 立即 `escalated` → 通知写入方按 reviewer-guide §7 修正，走 E 流程裁定 |
| `E_MISS` | 缺少必要键 | 否 | 同上 |
| `E_API` | multica API 调用失败 | 是 | 指数退避 30/60/120s ≤3 次；耗尽 → `escalated`（S2） |
| `E_WRITE` | 本地流水写入失败（OSError） | 是 | 同上 |
| `E_DUP` | 重复结算 | — | 幂等跳过（全局去重），非异常 |

## 九、事件生命周期

```
发现 / 告警 → 分诊定级（S1~S4）→ 处置恢复 → 全程通报 → 复盘（blameless）→ 闭环确认
```

- 全程通报：S1/S2 事件在 job issue 及总控 issue 留痕，升级时 @通知二线/三线。
- 闭环确认：处置完成后由一线责任人确认，S1 事件需复盘确认后才可关闭。

## 十、监控与度量

| 指标 | 目标 | 超限处置 |
|------|:---:|----------|
| 三任务 on-time 执行率 | >99%（月错误预算 ≈1 次失火） | 当月 ≥1 次失火 → blameless 复盘（L4） |
| 流水完整性 | 跨文件重复 issue = 0 | 立即 `--reconcile` + 复盘归属（`scripts/audit-events.py`） |
| pending 滞留 | 无 >48h 滞留 | 周报 + 告警（S2） |
| `escalated` 队列 | 48h 内升级/裁定 | 超时升级资深战略领导者（L3） |
| 静默失火 | 0（静默 = 故障） | 每日核验日志/run 存在，缺失即补触发 + 告警 |
| 各级别 SLA 达成率 | 响应/处置/恢复达标 | 周报呈现，不达标项复盘归因 |
| 复盘闭环率 | 行动项按期完成 | 周报跟踪 |

---

## 十一、事后复盘（Blameless）

- **触发**：所有 S1、当月 ≥1 次静默失火、数据错乱/双计、`escalated` 事件结案、SLA 达成率持续不达标。
- **流程**：事故响应指挥官主持 → 复盘五问（发生了什么 / 影响范围 / 根因 / 改进项 / 验收人）→ 输出行动项（责任人 + 截止时间）→ 结论写入复盘记录。
- **闭环**：复盘结论由资深战略领导者批准；改进项落实到具体 issue（assignee + 时限），跟进到关闭。

---

## 十二、时限待校准项（交资深战略领导者）

1. **时限数字**：第 5 节 S1~S4 的响应/处置/恢复时限为**建议基线**，可结合团队实际排班与 agent 异步触发节奏调整后固化。
2. **值守口径**：S1 是否需 7×24 值守，或按工作日（W/7x24）口径执行。
3. **固化范围**：是否将本 SLA 正式固化到 `docs/runbook.md` §3 并纳入监控周报指标（第 10 节）。
