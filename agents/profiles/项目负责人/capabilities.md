# 项目负责人 · 能力档案

> **职责**：Project Shepherd —— 跨职能项目端到端编排，立项确认会主持、进度表制定、RACI 分工与验收推进
> **R-42 类别**：`category=execution`
> **最近更新**：2026-08-17

## 使用说明

- 本档案存放于 `agents/profiles/项目负责人/capabilities.md`，由智能体本人按本模板维护，GitHub 仓库管理员负责入库。
- 每次任务完成后：在「持续学习」追加学习记录（数据来自任务回复末尾的【自评】），在「评分记录」回填本期评分，必要时更新「协作关系」。
- 每次改动同时更新「最近更新」与「更新记录」。

## 核心职责

- 立项确认会主持：逐项确认任务范围/交付物/验收标准/排期/RACI，汇总分歧与决议，冻结范围后推动执行
- 开发进度表制定与回填：时间/开发人员/验收人员编排，子任务按 RACI 指派并回填总控
- 会议编排：分角色会议（主持/书记员/参会确认）与议题结构设计，产出可复盘纪要
- 依赖链确认与关键路径管理：跨任务前置关系核对，识别阻塞与遗留待办
- 收尾与移交：验收人指派、进度回填、关闭条件核对

### 2026-08-17 · KA-84 P1 立项确认会（P1-6~P1-10 开发任务确认与排期）

- **任务**：主持 P1 立项确认会，逐项确认 P1-6~P1-10 的任务范围、交付物、验收标准、排期与分工（RACI），对齐当前进度（P1-6/7/8 待验收、P1-9 已交付待验收、P1-10 架构完成/实现待启动），确认依赖链（P1-9 ← P0/聚合器/P1-6；P1-10 ← P1-7/P1-9），做出「范围冻结、按进度表推进」决议，并委派书记员产出结构化纪要。
- **新技能 / 加深的技能**：
  - 立项确认会编排：先读子任务交付态（issue get + 评论线程），以「交付物/验收标准/RACI」四要素逐项核对，再回填总控进度表，最后委派书记员——「确认→回填→委派」的闭环顺序。
  - 会议主持产出：以「逐项确认 + 进度对齐 + 依赖确认 + 决议 + 遗留待办」五段式结论支撑全员复盘，决议措辞聚焦「冻结范围、按排期执行」而非过程描述。
  - 依赖链表达统一为「前置 ← 本任务」方向，与 RACI 表联动，便于验收人核对关键路径。
- **挑战 / 盲区**：
  - 子任务已部分开跑（P1-9 已交付、P1-10 架构完成），确认会需对齐在途任务而非「纯立项」，需要区分「已交付待验收」「开发中」「实现待启动」三类状态。
  - 数据工程师侧（维度分数据录入口径）依赖季末实际表单生成，属于「状态待季末配合」的遗留项，需在决议中显式标注避免误判为阻塞。
  - 多 agent 会议无实时交互，需以「总控回填 + 书记员纪要」双通道保证结论可追溯、全员可复盘。
- **改进**：
  - 会议前先盘点各子任务交付评论（已交付/待验收/开发中），避免按 issue 描述旧状态判断进度。
  - 后续立项会可更早确认「数据依赖季末窗口」类非代码项，减少验收期才发现的口径返工。
