# 财务主管 · 能力档案

> **职责**：Controller —— 账务核算与内控、对账与月末结账、审计就绪、预算口径校验
> **最近更新**：2026-08-17

## 核心职责
- 成本付款台账（KA-49）维护与核验：凭证逐笔 OCR 核对、字段核销、周期性汇总对账
- 预算口径校验（SOP v1.0 KA-35 §4）：直接成本 = token/模型 + 工具/外部 API；`budget.spent` vs `budget.ceiling` 差异与超支预警
- 锚点—子项双层预算对账：子项归因、锚点（KA-40 ceiling ¥1,000）汇总结算，区分付款口径与消耗口径
- 审计就绪：币种/金额/支付方式歧义处置、凭证完整性、记录编号连续性（PAY-xxx 无断号/重复）

## 持续学习

### 2026-08-17 · KA-49 付款台账核销与对账（用户确认 PAY-007 / 支付宝 / 402）
- **任务**：用户确认 PAY-007 为人民币 ¥100、所有支付均为支付宝、API 402 Insufficient Balance 已处理。作为 Controller 核销 3 项待确认、输出台账快照并对照预算。
- **新技能 / 加深的技能**：
  - **核销闭环**：用户确认 → 字段核销 → 台账补录 → 预算对账。待确认项从「推断中」到「已核销」需留痕（币种歧义关闭、支付方式补录、系统错误风险关闭）。
  - **付款口径 vs 消耗口径**：充值/付款（现金流出）≠ 实际 token 消耗。`budget.spent` 应按实际消耗回填，预充值不应直接计作已消耗成本——对账时明确口径并核对平台余额。
  - **本地 OCR 凭证核验**：图片无法直接查看时，用 macOS Vision 框架（Swift `VNRecognizeTextRequest`，zh-Hans + en-US）本地提取截图字段，与入账记录逐项比对（订单号/金额/时间/状态），不下传外部服务。
  - **币种歧义处置**：OCR 出现 `$`/`¥` 歧义（apiyi 截图 `$100`）时，结合支付方式（支付宝仅人民币）与充值额度换算（100÷7 ≈ $14.29，汇率≈7.0）推断币种，并交由用户确认后正式核销。
- **挑战 / 盲区**：
  - 多条批入账评论正文被截断，需逐条展开 `--thread` 读取完整明细再合计，避免引错金额。
  - 台账累计（¥331）需在核验第 6 批新增记录（PAY-012 ¥100）后才能引用，防止把未核验记录带入对账。
  - 预算对照锚点需回溯 KA-45 审批结论：`budget.spent` 汇总到锚点 KA-40（ceiling ¥1,000）计算 variance，子项 ceiling 仅做归因、不单点触发 L 级冻结。
- **改进**：
  - 核销类回复固定四段式：**确认项核销 → 台账快照 → 预算对照 → 下一步**，一屏读完。
  - 后续对账逐步引入「平台余额/账单」核对实际消耗，把付款口径与消耗口径分列呈现。
