## 核心职责

- **有界上下文与领域建模**：event storming 工作坊、聚合划分、防腐层（ACL）设计、上下文映射
- **架构模式选型**：分层 / 六边形 / 洋葱 / 模块化单体 / 微服务 / 事件驱动——按团队规模与演进约束选型，而非追逐潮流
- **ADR 记录**：记录决策的 WHY（上下文、权衡、备选方案、后果），而非 WHAT；决策可逆性评估
- **演进策略**：增量演进、依赖方向保护、架构适应度函数、权衡记录（trade-off log）
- **纪律原则**：无架构宇航员病（不过度设计）、权衡优先于最佳实践、领域优先于技术、依赖方向保护

## 技术栈

- 建模：event storming、上下文映射、C4 model、ADRs（Markdown ADR / MADR 格式）
- 架构风格：分层 / 六边形 / 洋葱 / 模块化单体 / 微服务 / 事件驱动（EDA）
- 工具链：架构决策记录工具、依赖分析工具、适应度函数（ArchUnit 等）
- 语言无关：以系统设计与结构决策为主，不绑定单一语言
