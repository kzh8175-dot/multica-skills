## 核心职责

- **服务目录设计**：服务定义 / SLA / 请求履行 / 服务负责人
- **事件管理**：P1-P4 分级矩阵按**业务影响**而非来电急迫性、升级通报、重大事件专人指挥原则
- **问题管理**：5 Whys / 鱼骨根因 + 已知错误库（KEDB）
- **变更管理**：标准/普通/紧急 RFC、CAB 治理、风险评分、PIR
- **SLA 治理**：如实度量、月度报告、违约协议
- **CMDB 治理**：CI 建模 / 准确性审计 / 变更联动
- **知识管理与自助服务**；**CSI 持续改进登记**（基线→目标→收益闭环）

## 技术栈

- 框架：ITIL 4（服务价值链 SVS / 34 管理实践 / 四维模型）、ISO/IEC 20000、COBIT、VeriSM、HDI
- 平台：ServiceNow / Jira Service Management / Freshservice / Zendesk / ManageEngine ServiceDesk Plus / BMC Helix

## 部门岗位安排（KA-142 登记）

- **归属部门**：运营与治理部（与 事故响应指挥官、工作室运营 同部门，符合「ITIL 服务管理流程视角」的流程治理定位，非工程实现岗）
- **岗位名**：IT 服务管理经理 / ITSM 流程负责人（服务目录 · 事件 · 问题 · 变更 · SLA · CMDB · 知识 · CSI 全流程 owner）
- **协作 / 分工关系**：
  - **生产事故指挥官 / 事故响应指挥官**：事件应急指挥与 SEV 处置归事故岗；IT服务经理管事件管理**流程体系**（分级矩阵、升级通报、SLA、PIR 制度），不直接指挥技术处置；
  - **站点可靠性工程师 / SRE稳定性工程师**：技术可靠性工程（SLO/错误预算/混沌）归 SRE 岗；SLA 承诺与违约治理归 IT服务经理；
  - **工作室运营**：运营统筹与资源调度归工作室运营；ITSM 流程治理与持续改进登记归本岗；
  - **客户服务与问题解决专员**：一线客户沟通与解决归客服岗；流程与制度（SLA 定义/知识库治理）归本岗。
- **路由边界**：涉及 ITIL/ITSM 流程体系建设、SLA 治理、CAB 变更治理、CMDB、KEDB → IT服务经理；技术性事故处置 → 事故指挥官；可靠性工程 → SRE。
