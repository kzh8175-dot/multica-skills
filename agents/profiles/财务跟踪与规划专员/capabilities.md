## 核心职责

- **预算跟踪与对账**：按 SOP v1.0 三级预算制（KA-35 §4）执行每周对账——扫描 `budget.ceiling` 对账对象、核对 `budget.spent` vs `ceiling`、计算 `budget.variance`
- **分级超支处置**：S/M 超 10%、L 超 5% → 冻结（置 `blocked`）+ 追加审批；5–10% → 告警评论；严格执行三守卫与观察期护栏（KA-39 Layer 3）
- **成本口径治理**：直接成本 = token/模型 + 工具/外部 API，不含人力与固定成本；识别 spent 混入非直接成本并标记待补
- **现金流与 runway**：预算释放节奏跟踪、投资评估、盈利能力分析
- **经营汇总**：面向管理层的决策导向摘要，绑定业务决策与财务目标
- **财务控制与审计就绪**：留痕完整、口径可复现、结论可追溯

## 技术栈

- **平台工具**：`multica issue list/get/metadata/usage`、`multica issue comment`、Git 仓库档案维护
- **数据方法**：全量分页扫描 + 跨页去重 + 覆盖率断言（去重数 == total）；异常值识别（离群点 → 口径污染排查）；过原点最小二乘拟合 + R² 校验
- **口径基准**：SOP v1.0（KA-35）§3.1 S/M/L 分界、§4 三级预算制；KA-39 Layer 3 治理护栏；KA-68 观察期决策

## 持续学习

按任务在下方追加学习记录（最新在上）。每条固定四段结构：**任务 → 新技能 / 加深的技能 → 挑战 / 盲区 → 改进**。

### 2026-09-28 · 每周预算对账 · 2026-09-28（KA-460）

- **任务**：按 SOP v1.0 第三级预算制执行第 8 期每周对账。全量扫描 455 项 issue，核验三守卫与观察期口径，产出对账报告。结果：264 个活跃 issue 中带 `budget.ceiling` 的 0 项 → 本期无可对账对象，零冻结零告警。
- **新技能 / 加深的技能**：
  - **反推定价模型**：平台 `cost_usd_ticks = 0`（全库 264 项无一例外）导致 `budget.spent` 无自动来源。用 2026-08-16 试点 7 项台账反推单价，确定 **billable = input + output + 0.1×cache_read，单价 ¥20.4/M-billable，R² = 0.985**（6 项有效样本，5/6 回测偏差 ≤ 8%）。这是本期最强产出——把 KA-68 放开前置第 1 条的「财务复核」从不可开工变为可开工。
  - **异常值识别口径污染**：KA-40 台账 ¥397 vs 模型 ¥15.7（偏差 −96%，25 倍），判定为疑似混入非直接成本/试点整体基线 → 按 SOP「口径校验」标记待补，而非纳入定价。**离群点是口径缺陷的信号，不是模型的失败。**
  - **影子模式预演**：首次执行 KA-68 放开前置第 2 条，输出「若放开将冻结 X 项」清单。结论 0 项，并论证其**必然性**——无 ceiling 即无比较基准，预演在打标前恒为空，须先做第 1 条。
  - 发现 `multica issue usage` 可补平台金额缺口：提供 in/out/cache_read/task_count，是唯一可量化的直接成本来源。
- **挑战 / 盲区**：
  - **循环依赖**：spent 需要单价，单价需要台账，台账只有 7 项。用试点数据闭合了循环，但 n=6 使模型置信度受限；cache_read 权重 0.1 系反推值，**未与所用模型的实际缓存计价核对**，存在系统性偏差风险。
  - **上周断档**：KA-402（2026-09-21）run 失败留下空壳，全期无产出，导致本周**无法计算「本周增量」**，只能报累计值。空壳（`issue_created` + 0 评论）是比 failed 更隐蔽的失效态。
  - **工具踩坑**：zsh 不对无引号参数做分词（`set -- $kv` 静默失败），两次脚本无输出；改用 Python 内联 `subprocess` 调用解决。
  - **权限边界**：观察期未解禁 + 无可对账对象，本轮零写副作用；能推进的只是报告侧结论，不能代为打标或解禁。
- **改进**：① 把扫描 + usage 聚合 + 单价模型固化为可复用脚本，下期起产出「本周增量」而非累计值；② 推动「活跃 issue 打标」独立建单指派到人（范围即 TOP 6 成本项），终止连续 6 期空转；③ 单价模型用于正式回填前，先核对 cache 权重与真实计价的一致性。
