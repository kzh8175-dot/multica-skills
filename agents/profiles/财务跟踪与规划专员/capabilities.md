# 财务跟踪与规划专员 · 能力档案

> **职责**：Finance Tracker —— 预算跟踪、现金流、成本效率与财务风险监控；SOP §4 三级预算对账主责
> **最近更新**：2026-08-17

## 核心职责
- 每周预算对账（SOP §4）：扫描 `budget.ceiling` 分母，按周回填 `budget.spent` / `budget.variance`，产出真实超支预警
- 成本核算：直接成本口径（token/模型 + 工具/外部 API，不含人力与固定成本），模型用量 × 定价换算
- 预算分级（S/M/L）与门禁判定：锚点级超支阈值（S/M 超 10%、L 超 5% 冻结；5–10% 告警；≤5% 周报）
- 财务风险预警与改进建议（附 RACI 与截止）

## 持续学习

### 2026-08-17 · KA-95 每周预算对账首跑（空扫描，观察期只读+报告）
- **任务**：按 SOP v1.0（KA-35）第三级预算制执行每周对账 autopilot：扫描本工作区所有 status 非 done/cancelled 且带 `budget.ceiling` 的 issue，核对 `budget.spent` vs `budget.ceiling`，超支按分级阈值告警/冻结，产出本周对账报告（如实报告不掩盖）。
- **新技能 / 加深的技能**：
  - **全量扫描方法**：`multica issue list --limit N --output json` 一次性拉取全工作区（`has_more=false` 即覆盖 100%），用脚本按 status + metadata 键过滤，快速定位预算载体 issue；本次 93 项全覆盖，23 项活跃（非 done/cancelled）。
  - **空扫描如实处理**：23 项活跃 issue 均无 `budget.ceiling` 元数据 → 明确写「本期无可对账」，不臆造结论、不强行制造告警（对应 KA-39 护栏「空扫描」条款）。
  - **活跃项 vs 已结束项基线区分**：7 个带 budget 元数据的 issue 全部 `done`（如 KA-19 曾 +31% 超支、KA-40 锚点）→ 不做冻结/告警，仅留作历史基线；对账对象严格限定为「非 done/cancelled 且带 ceiling」。
  - **覆盖校验**：`issue list` 返回的 metadata 与逐项 `issue metadata list` 直接读取一致（抽查 6 个活跃项确认），避免 list 截断导致的漏扫误判。
  - **观察期口径**：当前处于上线后 2 周「只读+报告」观察期（KA-39 护栏），即使存在超支项也只出告警与升级建议、不实际置 blocked；期满复核衔接 KA-68。
- **挑战 / 盲区**：
  - 本期无可对账对象，冻结/告警/数据缺口分支未实际命中，逻辑只能静态核验（阈值边界、三守卫、L 级 5% 无告警带等）；观察期结束后的首个真实超支周需重点复核。
  - 需区分「从未打标（无 budget 元数据）」与「spent 缺失（有 ceiling 无 spent）」两类空态：本期属前者，按空扫描处理；后者才按数据缺口上报。
- **改进**：
  - 将对账的「扫描—过滤—核对」步骤沉淀为可复用脚本/技能，减少每周手工重复，并在报告中给出分子覆盖（活跃数 / 打标数 / 对账对象数）让空扫描结论可复核。
  - 观察期（前 2 周）内建议保留「只读+报告」而非自动冻结，避免上线初期误冻结；期满按 KA-68 复核后放开。

### 2026-08-17 · KA-66 预算 spent/variance 首轮回填（锚点 KA-40 + 14 P0 子项）
- **任务**：SOP 试点 KA-40 切轨后，为锚点及 14 个 P0 子项回填 `budget.spent`、计算 `budget.variance = spent ÷ ceiling − 1`，让预算对账 autopilot 从空转转为真实产出。
- **新技能 / 加深的技能**：
  - **实际成本反推法**：`multica issue usage <id>` 返回 input/output/cache_read token 与 task_count；`cost_usd_ticks=0` 说明平台未记账，需自行按「用量 × 定价」换算。cache_read 被标为 uncosted → 与权威基线 ¥397 交叉校准后确认按 ¥0 计入（若按 10% 计入会远超基线，口径不一致）。
  - **用量—基线一致性校验**：先建立 pricing 假设 → 计算子项合计 → 与已知基线（`baseline.cost_cny=397`）比对，确认子项合计 ≤ 锚点总额、差额量级与取消重复件估算（KA-9~13 ≈¥141）相符，再落盘。
  - **锚点—子项双层预算语义**（KA-45 批准口径）：冻结/超支阈值按**锚点级**（KA-40 ceiling ¥1000）判定；子项 ceiling 仅归因核算、不单点触发 L-5% 冻结。子项超支（如 KA-19 +31%，Opus 模型漂移所致）→ 周报跟踪 + 归因到根因（复盘 P-2 / I-2 模型纪律），不据此冻结。
  - **数据缺口如实处理**：task_count=0 的 backlog 项（8 个错峰批）无实耗 → 标注「待测」，**不硬填、不按 0 处理**（对账 autopilot 守卫②：spent 缺失 → 按数据缺口报告）；避免把「未开始」误报为「零成本完成」。
  - metadata 写入命令：`multica issue metadata set <id> --key budget.spent --value <num> --type number`（数字类型支持小数）。
- **挑战 / 盲区**：
  - usage 接口无按模型拆分，只能以复盘结论（Opus 占成本 92%）做单模型假设 → 用 Opus 5 定价（$5/$25 per M）为保守口径，并在报告中声明假设与敏感度（cache 计入则 KA-18 +111%）。
  - 已完成子项（done）不在 autopilot 扫描范围（仅扫非 done/cancelled），锚点已 done → 已完成项的真实 spent 数据需靠周度对账人工复核（KA-41 式）消费，autopilot 只对活跃项（8 个 backlog）产出「数据缺口」报告。
  - 基线 ¥397 与当前用量合计存在差额（¥397 vs 子项归因 ¥268.7 + 锚点自用 ¥21.9）：差额 ≈ 取消重复件 + 未归因历史项，量级合理，如实说明而非强行平账。
- **改进**：
  - 回填前先建立「pricing 假设 + 基线校准」两步，避免模型口径漂移；把 cache_read 是否计入的判定做成 SOP 口径备注。
  - 与财务规划与分析分析师对齐「计划口径（S2） vs 实际口径（Opus）」双线展示，variance 分「计划基准」与「实际驱动」两层说明。

## 待提升的方向
- 向平台确认是否有按 run 的模型级用量明细（成本 ticks 或模型标签），替代单模型定价假设。
- 推动 SOP §4 补充「cache_read 是否计入直接成本」的明确口径，避免各轮次估算不一致。
- 探索把已 done 项目的锚点级 variance 纳入对账报告自动汇总（当前 autopilot 只扫活跃项）。
- 将对账扫描沉淀为脚本/技能，并在报告中给出覆盖分子（活跃数/打标数/对账对象数），让空扫描可复核。
