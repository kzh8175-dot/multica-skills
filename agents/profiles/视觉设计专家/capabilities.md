## 核心职责

- 视觉叙事：为复杂信息构建"KPI → 排行 → 明细 → 治理"的分层叙事结构与情感节奏。
- UI 原型：产出自包含 HTML 高保真原型（浏览器可直接打开），覆盖多视觉方向（数据大屏深色 / 后台管理浅色 / 简洁运营轻量）。
- 数据可视化：按可访问性规范设计图表（色板可计算校验、单一 Y 轴、细线弱网格、图例与表格视图、tooltip 悬停）。
- 字段级来源标注：将原型数据字段与业务数据模型（如评分方案 C 的 R-xx / E-xx / budget.xx）逐一对应标注，保证"分数从哪来"可追溯。
- 跨平台适配：大屏 / Web 后台 / 运营视图的视觉系统统一与差异化。

### 2026-08-17 · KA-87 智能看板原型 A · 数据大屏（深色）

- **任务**：为评分方案 C 的智能看板产出 1 套完整 UI 原型，视觉方向为"数据大屏（深色高对比，面向管理者监控）"，覆盖 Overview / Leaderboard / Trends / Score Detail / Event Stream / Budget / Promotion / Escalation 8 个核心页面，所有数据字段标注来源，附设计说明。
- **新技能 / 加深的技能**：
  - 单文件自包含数据大屏原型工程：一个 HTML 文件（HTML+CSS+内联 SVG+JS）交付 9 个视图页面，零外部依赖，浏览器直接打开；用 hash 深链实现页面直达（`#overview` 等）。
  - "数据大屏"视觉语义与"安静图表规范"的平衡：深空蓝黑底 + 青色发光强调 + 面板角标营造监控大屏氛围，但保持细线、弱网格、克制高亮——数据是唯一"吵"的元素，chrome 保持安静。
  - 数据模型驱动的跨页一致性：用同一份 JS `DATA` 对象驱动全部图表与表格（排行榜、明细、事件流、预算由同一数据源生成），避免"各页面数字对不上"。
  - 字段级来源标注系统：`src` 徽标 + 悬停/点击 tooltip + 浮动"数据来源图例"面板 + 设计说明页图例，把评分方案 C 的 R-01~R-33 / R-41 / R-51 / R-52~55 / R-71 / R-72 / E-01~E-07 / budget.ceiling|spent|variance 全部落到具体字段。
  - 数据可视化可访问性落地：≥2 系列必有图例；多线收敛时不直接标端值（会碰撞），改"图例 + 十字线 + tooltip"；状态色（R-71/R-72/E-02 标记）带图标+标签不单靠颜色；等级 S/A/B/C/D 恒定配色且必带字母；数据列用 tabular-nums。
- **挑战 / 盲区**：
  - "大屏审美"与"图表规范"的张力：经典大屏爱用厚柱、高饱和、重网格，而规范要求细线、弱网格、留白。解法是把"大屏感"放到页面 chrome（背景网格、角标、发光、顶部状态条），图表内部保持规范。
  - 本环境无法直接预览渲染图像（图像读取不可用），改为 headless Chrome `--dump-dom` + console error 扫描 + PNG 像素亮度统计三重验证渲染正确性，并在交付前用 JS 语法检查 + HTML 标签平衡检查兜底。
  - 多系列折线端标签碰撞：6 条分类趋势线端值接近，直接标值必然重叠；按规范改为图例+tooltip，避免视觉噪声。
- **改进**：
  - 后续复杂原型先做"数据模型 → 页面字段映射表"，再写实现，减少字段漏标。
  - 交付前固定跑一遍无头浏览器冒烟（关键数据断言 + 零 console error），并保留关键页截图作为附件。
  - 可引入色板校验脚本（dataviz 的 validate_palette）对原型色板做一次硬校验，把"看起来对"升级为"可验证对"。
