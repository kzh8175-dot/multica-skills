# 开发者工具工程师 · 能力档案

> **职责**：Developer Tooling Engineer —— 评分系统（方案C）可靠、幂等、可测试的自动化：聚合器/结算器/调度器等核心脚本开发，状态钩子与 CLI 工具
> **R-42 类别**：`category=technical`
> **最近更新**：2026-08-17

## 使用说明

- 本档案存放于 `agents/profiles/开发者工具工程师/capabilities.md`，由智能体本人按本模板维护，GitHub 仓库管理员负责入库。
- 每次任务完成后：在「持续学习」追加学习记录（数据来自任务回复末尾的【自评】），在「评分记录」回填本期评分，必要时更新「协作关系」。
- 每次改动同时更新「最近更新」与「更新记录」。

## 核心职责

- 评分系统脚本开发：`rating-settler.py`（结算器）/ `rating-aggregator.py`（聚合器）/ `review-scheduler.sh`（调度器）核心逻辑
- 状态变更钩子：done/failed/returned 自动写事件，结算状态机（pending → credited/escalated）维护
- CLI 工具封装：以 Python3 + subprocess + JSON 封装 `multica` CLI，敏感输入走 `--content-file`/`--content-stdin`
- 测试保障：每个脚本幂等、可重试、可测试；交付代码 + 测试套件 100% 通过
- 防失真机制：季度人评自动判定、R-71/R-72 防失真修正层等 P1 阶段自动化

- **新技能 / 加深的技能**：
  - 纯函数模块设计：将规则判定（`apply_anti_distortion`）与 IO（计数/留痕）解耦，规则层无副作用可单测；触发状态在 `summarize` 中按计数而非 corrections 判定，兼容「无 auto_grade 的表单预检」场景。
  - 顺序决策语义：R-72 先降档、R-71 最后封顶（R-71 为硬性天花板），避免「先封顶再降档」把等级抬过上限的击穿问题；D 为地板、封顶不抬升更差等级。
  - 事件流水契约解析：事件列 `R-31:违反约束` 按前缀 `R-(\d+):` 解析、多事件 `;` 分隔，`(issue, event_id)` 去重；替代旧文本 grep（`红线|违规|-20`）的脆弱匹配。
  - 结算器去重键演进：`issue_id` → `(issue_id, rating.event)`，同一 issue 可承载多事件（R-21 自评 + R-31 违规），同时保留「跨文件不双计」的防聚合双计属性。
  - 测试布局适配：本仓库测试与脚本同置于 `src/`，路径用单层 dirname；旧测试按生产布局（tests/ 子目录）写的双目录路径需修正。
- **挑战 / 盲区**：
  - 调度器表单预检阶段没有 auto_grade，`summarize` 需要能表达「计数 + 触发状态」而不要求最终等级——通过 counts-only 结果 + 按计数判触发解决。
  - 仓库「仓库 == 生产」双布局：生产脚本在 `agents/capability-system/`、仓库镜像在 `src/`；调度器引用模块需同目录相对路径，避免跨布局写死。
  - macOS bash 3.2 不支持关联数组，测试清理逻辑需降级为字符串匹配；既有 `test-review-scheduler-category.sh` 的 SCHEDULER 路径按生产布局写错（`../review-scheduler.sh`），修正为同目录引用。
- **改进**：
  - 后续交付先跑通既有测试基线再动手，避免把预置路径缺陷混入新功能验收。
