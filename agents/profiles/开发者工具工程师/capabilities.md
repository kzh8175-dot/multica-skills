- **新技能 / 加深的技能**：
  - 「静默截断」类数据完整性问题：单次 `--limit N` 在数据量增长后静默丢尾部——修复选分页（offset 游标）而非简单提 limit，防工作区无限增长；用 CLI 返回的 `has_more`/`total` 字段做精确终止信号，无字段的老 CLI 以「非满页」兜底。
  - 分页健壮性三件套：① 终止条件多信号（has_more=false / 非满页 / 空页，任一命中即止）；② 最大页数护栏防死循环；③ 中途页失败降级「返回已拉取部分 + note」，而非整批失败（best-effort 契约，与 budget 原 note 语义一致）。
  - offset 分页的并发插入防御：分页期间工作区新增 issue 会整体偏移导致重复/遗漏——按 id 去重（保留首现）为低成本防御，纳入测试。
  - 行为等价验证：重构后跑「新分页 vs 旧单页」对比（97 issues < 200 时逐位一致），证明分页重构无回归、且真实 CLI 响应形态被正确消费。
- **挑战 / 盲区**：
  - `has_more` 是 CLI 返回的 JSON bool（false→False），老 CLI/裸数组响应无此字段——终止判断必须 has_more + 非满页双信号，不能只依赖一个。
  - 数据量恰为 page_size 倍数时，「非满页」判断会多拉一页空页；真实 CLI 的 has_more=false 能在满页处提前终止——测试需分别覆盖 has_more 存在与缺失两种形态。
  - 中途页失败的行为取舍：整批失败（保一致）vs 部分返回 + note（保可用）——看板只读展示场景选后者更符合 best-effort，且与离线 `--no-cli` 的 note 语义对齐。
- **改进**：所有经 CLI 拉取列表的聚合，交付前自检「数据量是否可能超过单页 limit」；分页/翻页逻辑一律用 mock 覆盖「恰好倍数 + 超量 + 中途失败 + 并发插入」四类用例；重构后跑新旧路径行为等价对比作为回归证据。
